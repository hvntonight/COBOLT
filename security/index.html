Security and recovery

Local encryption should come with a clear explanation of how you get your files back—and what encryption does not protect.

Updated October 24, 2026. Advanced editing, content search and full backup rehearsal are candidate features, not yet in the public 1.0 release.

Your files do not depend on a purchase

Keep a complete copy of the closed .vault directory and your password or recovery key. On another Mac, choose Open Existing Vault and unlock it with the same password. Touch ID does not travel with the vault. The candidate keeps read-only unlock, preview, export, historical-version export and encrypted backup free, without a purchase or Cobolt account. The current public 1.0 is fully unlocked.

Keep a key outside the vault

Every new vault generates a recovery key shown once. Save it separately, preferably away from the Mac. If both the password and recovery key are lost, support cannot bypass encryption. A long, unique passphrase is much stronger than the permitted six-character minimum. The app’s attempt delay does not prevent offline guessing against a copied vault.

Test recovery, not just copying

Use a separate disk for a backup. In the candidate, an unlocked backup is called verified only after current files, encrypted Trash and historical versions authenticate. A locked backup is an unverified encrypted copy. Test a backup independently, export a disposable sample and compare it with the original before relying on it. Verification is not a substitute for retaining separate copies.

The local interface and plaintext boundary

Passwords are entered in the bundled local React interface and passed to Swift through a local WebKit bridge. The recovery key is displayed there once. Master keys and file-content encryption remain native. No password, key or file is uploaded to a Cobolt server.

Quick Look, external editing and exports can create plaintext files. External editors can keep their own caches or unsaved documents. In the candidate, locking saves working copies first; a failed save postpones locking or quitting and shows a warning. Finish or discard edits before leaving the Mac, and also lock your macOS account. SSD deletion and Swift/OS memory cleanup are best effort, not forensic-erasure guarantees.

Candidate content search and opt-in OCR run on-device. Text is cached only in bounded memory and cleared on lock; it is not published to Spotlight. Unsupported/unreadable files are skipped, and basic English OCR is disclosed when advanced recognition is unavailable.

A documented format, not a security certification

Format 3 uses a random 256-bit master key, password PBKDF2-HMAC-SHA256, per-file HKDF-SHA256 keys and AES-GCM authenticated chunks and manifests. Vault names and some local app metadata remain visible; original file names, tags and source references inside the manifest are encrypted. The directory is portable, not a cloud-sync conflict-merging format. An independent security audit has not yet been completed.

Ask for help without sharing secrets

For support, share the Cobolt/macOS version, a non-sensitive error message and reproduction steps using synthetic files. Never post passwords, recovery keys, original private files or identity documents in a public issue.
